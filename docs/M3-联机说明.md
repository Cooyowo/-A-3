# M3 在线对战 · 使用与实现说明

> 目标：4 人各自用一台设备（或 4 个浏览器窗口）打完一整局；**服务端权威、客户端看不到别人的手牌**；断线 30 秒内可重连。

---

## 一、怎么跑（本地联调）

需要 **两个终端**（服务器和前端各一个）：

**终端 1：启动服务端**
```powershell
cd D:\Project2026\a3-v1
npm.cmd run dev:server
```
预期看到：
```
葵A葵3 服务端已启动：http://localhost:3000（WebSocket: ws://localhost:3000/ws）
```
> 它会先用 Vite 把 `apps/server` 打成 `apps/server/dist/main.mjs` 再运行（本机 tsx 跑不起来，原因见文末）。

**终端 2：启动前端**
```powershell
cd D:\Project2026\a3-v1
npm.cmd run dev:web
```
浏览器打开 `http://localhost:5173` → 首页点 **「在线对战」**。

**4 个人怎么玩**
1. 第一个人：填昵称 →「创建房间」→ 看到 6 位邀请码（如 `4JTVBW`）→「复制邀请码」发给朋友；
2. 另外三个人：填昵称 + 输入邀请码 →「加入房间」；
3. **4 人齐了自动发牌开局**（不用点开始），之后和本地热座一样点牌出牌；
4. 同一局结束后服务端自动发下一局（结算面板下方有倒计时）。

**手机**：连同一个 WiFi，打开终端里 `Network:` 那行地址（如 `http://172.26.203.197:5173`），横屏；WebSocket 会自动连到同一台电脑的 3000 端口。

**停止**：两个终端各按 `Ctrl + C`。

**换端口/换机器**：前端支持环境变量 `VITE_WS_URL` 覆盖 WebSocket 地址（M4 部署成同源 `/ws` 时不用设置）。

## 二、实现结构

```
apps/server/
  src/protocol.ts        —— 转出口，真正协议在 packages/protocol
  src/room.ts            —— 房间（4 座位/邀请码/开局/定时推进/重连）
  src/server.ts          —— Fastify（HTTP 健康检查、建房、查房）+ ws（/ws）
  src/main.ts            —— 启动入口
  vite.config.ts         —— SSR 构建成单文件 dist/main.mjs
  tests/room.test.ts     —— 房间逻辑 / 隐藏信息 / deadline
  tests/http.test.ts     —— HTTP 接口
  tests/e2e.test.ts      —— 真实 WebSocket 4 客户端整局 + 断线重连 + 非法动作

packages/protocol/       —— 客户端与服务端共用的协议类型 + zod 校验
apps/web/src/game/online/
  net.ts                 —— WebSocket 连接（自动重连 + 心跳 + 回前台补连）
  adapter.ts             —— PlayerView → GameState（界面层零改动复用）
  store.ts               —— 联机 store（房间/视图/动作上报/重连 token）
apps/web/src/components/
  Lobby.tsx              —— 大厅（建/加入房间、邀请码、4 座位等待）
  OnlineApp.tsx          —— 联机总入口（大厅 ↔ 牌桌 + 连接状态条）
  OnlineTable.tsx        —— 联机牌桌（复用 M2 的牌/座位/场景组件）
```

**关键设计**

1. **服务端权威**：发牌、合法动作、结算、供牌、锁定全在服务端跑 `@a3/core`；客户端只发动作，收到 `PlayerView` 后渲染。
2. **隐藏信息**：`PlayerView` 只带**自己的手牌**；别人的只有 `handCount`。客户端适配器用**负数占位牌**凑张数，别人的牌面根本不在客户端内存里（`e2e.test.ts` 有专门的泄露断言）。
3. **计时在服务端**：明牌 4s / 供牌展示 4s / 回牌 20s / 挑回牌 15s / 锁定 5s / 下一局 5s，超时自动落子；`view.deadline` 是 epoch ms，前端只负责显示倒计时（不受两端时钟差影响）。
4. **断线重连**：进房时拿 `token` 存 localStorage；断线后自动指数退避重连并 `resume`，30 秒内回原座位、拿回自己的手牌。
5. **大厅与开局**：房间创建后只占座不发牌，**满 4 人才发牌**；等待时显示邀请码和 4 个座位。

## 三、验收（对应 START-HERE M3 标准）

| 标准 | 怎么验 |
|---|---|
| 4 个窗口打完一局 | 按第一节开 4 个浏览器窗口（或无痕/手机）建+加入房间，点完一局看结算 |
| 客户端看不到别家手牌 | ① 开发者工具 Network → WS → 看每条 `view` 只有自己的 `hand`；② `npm.cmd run e2e` 自动断言 |
| 断线 30s 内重连 | 打牌中途关掉一个窗口的标签页/断网几秒再打开，应回到原座位并恢复手牌；`e2e.test.ts` 也覆盖 |
| 服务端权威 | 非法动作（如空牌 PLAY）只返回错误，不改变牌局（`e2e.test.ts` 第三条） |

## 四、已知限制 / 留给 M4

1. **出牌回合没有强制超时**（Q-033 v1 不做托管）：有人长时间不出，其他三人会一直等；掉线超过 30 秒后座位会保留但牌局卡住，需要大家退出重开。
2. 房间不会自动回收（服务端重启即清空）；人数不足 4 人时不会自动开始。
3. 没有账号体系，昵称只在房间内有效；没有观战。
4. 部署（M4）时前端与 `/ws` 同源，由 Caddy 反代到 app 容器。

## 五、为什么服务端不用 tsx

本机受限环境里 tsx 依赖的 esbuild 会 `spawn EPERM`（沙箱禁止子进程管道）。所以 `apps/server` 用 **Vite SSR 构建**（`vite build` → `dist/main.mjs`），把 `@a3/core`、`@a3/protocol` 一起打进 bundle，只把 fastify/ws/zod 留作外部依赖：
```powershell
npm.cmd run build --workspace @a3/server   # 产物 apps/server/dist/main.mjs
npm.cmd run start --workspace @a3/server   # 直接跑产物
```
