**做了什么**：一个页面摆四家牌，浏览器里能手动打完一整局（发牌 → 明牌 → 供牌/回牌 → 锁定窗口 → 出牌 → 结算 → 下一局）。

| 层 | 文件 | 内容 |
|---|---|---|
| 引擎接线 | `apps/web/src/game/store.ts` | Zustand store：把 `@a3/core` 的状态机包成「点按钮 → 动作 → 推进」；引擎抛错转成界面提示，不崩页 |
| 派生数据 | `apps/web/src/game/selectors.ts` | 当前行动者、阶段标题、座位状态、供牌视图、结算视图、下一局供牌/首发文案、身份公开规则 |
| 视觉组件 | `components/CardView.tsx` / `HandView.tsx` / `SeatPanel.tsx` / `TableCenter.tsx` | 纯 CSS 牌面（无图片）、手牌叠放、座位卡片、桌面中央 |
| 阶段面板 | `components/PhasePanels.tsx` | 明牌决策、供牌信息、选回牌、挑回牌、锁定窗口、结算、底部操作条、提示条 |
| 样式 | `styles.css` / `styles/cards.css` / `styles/panels.css` | 深绿牌桌 + 金色点缀；手机竖屏 390px 优先 |
| 总装 | `App.tsx` | 阶段 → 面板路由、非法操作提示、规则速查 |

**交互口径（本轮采用的默认值）**：点选牌 + 底部「出牌」按钮；纯 CSS 牌面；同一屏轮流操作、只显示当前行动者的手牌（其他人显示牌背与张数）。

| 纯引擎端到端 | `apps/web/tests/hotseat.test.ts` | 用 store 动作连打 **10 局**不报错，结算数字与规则一致 |
| 视觉验收 | 无头 Edge 截图（390×844） | 见 `screenshots/m2-*.png` |

**设计决定（M2 特有）**

1. **只显示当前行动者的手牌**：热座同屏玩，轮到谁就把谁的 13 张亮出来；其他人只显示牌背 + 张数（`SeatPanel`）。
2. **身份公开规则**：只在「自己行动 / 明牌后 / 结算后 / 该座位打出过地主牌」时显示身份，其它情况显示「身份未公开」。
3. **锁定窗口没有 5 秒倒计时**：热座场景由每个达标玩家自己拨开关后点「开始出牌」推进（Q-002：热座禁用倒计时；Q-053 的 5 秒固定窗口是 M3 服务端口径）。
4. **12 张供不出**：在供牌阶段直接给「明牌（债务作废）/ 重新发牌（债务保留）」两个按钮（Q-008 合并成一次决策）。
5. **不用 SSR 做界面测试**：zustand v5 的 SSR 快照永远取初始 state，静止渲染测不出其它阶段，所以界面测试统一用 jsdom + Testing Library 真实挂载。

**已知限制 / 留给 M3**

1. 热座是同屏共享，**隐藏信息在物理上无法真正隔离**（锁定资格、明牌选择都能被旁边的人看到）；M3 每人一台设备后由服务端隔离手牌。
2. 出牌阶段没有回合计时与托管（Q-033 v1 不做）。
3. 手牌 13 张时叠放后每张可见约 22px，点选需要一点准头；真机验收若觉得难点，可以把叠放比例放宽或加「点中间区域放大」。
4. 结算面板在 844px 高度下需要轻微滚动（底部「下一局」按钮可见，供牌预告部分需要滑一下）。

**下一步**：M3 在线对战（房间创建/加入、邀请码、4 人各自设备、服务端权威裁判、断线 30s 内重连）。

**做了什么**：`packages/core/src/` 完整规则引擎（纯函数、零依赖、零 IO、随机源注入）

**本机环境坑（已解决/已规避）**

1. 工作区 Windows 文件权限缺「完全控制」→ 已用权限诊断脚本修复（有备份与回滚脚本）。
2. `git` 的 schannel TLS 后端报 `SEC_E_NO_CREDENTIALS` → 仓库内固定 `http.sslBackend=openssl`。
